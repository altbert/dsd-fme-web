# TODO

Open bugs and planned work for this fork, mostly the web interface. Bugs in the original DSD-FME are reported to [lwvmobile/dsd-fme](https://github.com/lwvmobile/dsd-fme) instead of fixed here, so merges stay easy; the ones seen so far are listed at the end.

## Fix

- [ ] **Random crashes in long `-i rtl --web` sessions.** `coredumpctl list dsd-fme` holds eight crashes of `./dsd-fme -i rtl --web 8083` since 2026-10-21; `coredumpctl info <pid>` shows each stack.
  - SIGSEGV 2026-10-26 (build 5caaf7c): `getFrameSync` writing a dibit through `state->dibit_buf_p` (dsd_frame_sync.c:330). The pointer held 0x7fbe00000320, a heap address whose low 32 bits had been replaced by 800: it was overwritten, not run off the buffer (every write checks the bound). `dibit_buf_p` is the second field of `dsd_state`, and `opts` and `state` are locals of `main`, so the stray write came from outside the struct, probably a neighbor on `main`'s stack.
  - SIGSEGV 2026-10-22: `watchdog_event_history` reading through a pointer mangled the same way (0xfffff9fd00000745).
  - SIGSEGV 2026-10-22: in libc under `pa_simple_write`, from `playSynthesizedVoiceMS` (P25 voice, `processLDU1`).
  - SIGFPE 2026-10-22 and 2026-10-25: `getSymbol`, whose only division by a variable is `symbol = sum / count` (dsd_symbol.c:599). `count` stays 0 when no sample lands in the window it averages, which depends on `symbolCenter`, `samplesPerSymbol` and `rf_mod`: a mode switch may leave them inconsistent.
  - SIGFPE ×3 2026-10-21: `dc_block_filter` dividing by a `result_len` of 0 in the RTL demod thread. Not seen since.
  - Next: run the usual session on an ASan/UBSan build, which reports a stray write where it happens.

- [ ] **rtl_tcp: capture rate, bandwidth and RTL AGC from the web.** `rtl_dev_set_rate`, `rtl_dev_set_bandwidth` and `rtl_dev_set_agc` (src/rtl_sdr_fm.cpp) call librtlsdr directly, but with `-i rtltcp` there is no local device. After a rate or bandwidth change the tuner isn't re-centered, so the receiver ends up off frequency, and the AGC toggle fails with a warning. Use `rtlsdr_or_tcp_set_center_freq`; AGC needs an rtl_tcp wrapper (the protocol has a set-AGC-mode command) or the toggle hidden over rtl_tcp. Found by reading the code, not reproduced yet.
- [ ] **Spectrum edge alias.** The dongle captures from f − rate/4 to f + 3·rate/4, so the leftmost quarter of the spectrum and waterfall shows signals from the top of the capture, one sample rate higher than drawn. Clicking there tunes to the wrong frequency. The band scan already skips that part; grey it out or leave it undrawn on the page too.
- [ ] **Slow to react at 0.25 MSPS.** The decoder thread applies the page's commands between symbols, and it waits for each USB transfer: librtlsdr's default 256 KiB (`rtlsdr_read_async` with `buf_len` 0 in rtl_sdr_fm.cpp; rtl_tcp uses the same block size), 520 ms at the 252 kSPS of the 0.25 MSPS choice. A tune or a setting takes up to that long to apply (a `get_status` round trip with a stand-in librtlsdr: median 458 ms at 0.25 MSPS, 107 ms at the default rate), and decoding runs as far behind. Smaller transfers at low rates would fix both: a `buf_len` scaled to the rate in upstream's `rtlsdr_read_async` call, fixed when the read starts, so a rate change from the web would restart it. The spectrum paces its own frames and isn't affected.
- [ ] **Auto-tune can't center a nearby carrier and hops between carriers.** `run_auto_tune` (src/dsd_web.c) snaps to the strongest bin within ±1/6 of the span, skipping ±8 kHz around the center (`guard`, for the DC tone), and wants it 8× over the mean of that window, guard included. Tuned a few kHz off a carrier, that carrier sits in the guard: it can't be centered, and its power lifts the mean over every other peak, so nothing snaps. With two carriers in reach it jumps between them every 2 s (seen live with two DMR repeaters 60 kHz apart, tuned 2 kHz off one). On the 2-FFT frames the spectrum had before 2026-11-06, noise spikes passed the 8× test by chance, so it snapped anyway, to the other carrier. Leave the guard out of the mean, take the nearest clear peak instead of the strongest, and keep the guard to the few bins of the DC tone, which sits exactly at the tuned frequency.
- [ ] **No browser voice from P25 Phase 1, NXDN, dPMR, ProVoice and some YSF modes with `-o null`.** `-o null` also sets `audio_out = 0` (dsd_main.c), and `processMbeFrame` (src/dsd_mbe.c) runs `processAudio` on its single-channel path only when `audio_out == 1`. Without it `state->audio_out_idx` stays 0, so `playSynthesizedVoiceMS` has no samples for `web_audio_push`. The stereo path (DMR, TDMA, auto), D-STAR, M17, analog and `-y` float output aren't affected. The end of `processMbeFrame` sets `audio_out` back to 0 for the null output, so the web layer can't just raise it; a tap on that condition (`audio_out == 1 || opts->web_enable == 1`) would. Found by reading the code, not reproduced yet: it needs a single-channel voice capture.
- [ ] **The band scan bookmarks one carrier twice.** A carrier's frequency is measured from its spectrum (the centroid between its -6 dB edges), which wanders ±2 kHz between passes on 4FSK; `bs_save` (src/dsd_web.c) snaps it to the 6.25 kHz raster only within 1 kHz and `bm_near` treats bookmarks within 2.5 kHz as the same, so a later pass can add the same station again 3 kHz away (seen with the stand-in librtlsdr's M17 station: two "M17" bookmarks 3 kHz apart in 200 s). Snapping within half a raster step (3.1 kHz), or a wider `bm_near` for band scan finds, would keep one.
- [ ] **The band scan can miss a carrier on a window edge.** Windows are spread evenly over the range, so one window's dongle DC (tuned + rate/4) can land on the next window's lower edge: with 400 kHz windows it fell 1 kHz under it. A carrier there is dropped by the first window as that DC tone (`bs_find_peaks` skips ±2 kHz around it) and by the next one when its measured centre comes out a little under the edge (`f < flo`; it wanders ±2 kHz). Seen with the stand-in librtlsdr: a toned FM station on the edge was found in one run and missed in the next. Letting the windows overlap by a few kHz, or not dropping a peak under `flo` that the previous window dropped as its DC, would keep it.

## Add

- [ ] **Voice transcription.** Turn decoded calls into text with a local speech-to-text model (Whisper through whisper.cpp, which is MIT-licensed C/C++ and runs on a CPU, or another model that works offline) and show the text on the call's activity item, searchable with the filter.
  - Local only: the audio is other people's traffic, so no cloud services.
  - Off the decoder thread: a worker thread or a helper process, fed one finished call at a time. The per-call WAVs already exist, so a first version can transcribe those.
  - Decoded voice is 8 kHz vocoder audio and Whisper takes 16 kHz, so resample, and expect rough accuracy; mark transcripts as machine-made.
  - Skip calls muted for a missing key. Optional at build time (a cmake switch) and at run time (a flag or a toggle).
- [ ] **Trunking card for DMR and NXDN.** The talkgroup list, the follow reasons and the followed call come from P25 control channels only (the TSBK tap in p25p1_tsbk.c). On DMR (Capacity Plus, Connect Plus, Tier III, XPT) and NXDN systems the decoder still follows calls, but the card shows no grants.
- [ ] **Other SDR hardware directly** (SoapySDR or similar), so HackRF, Airspy, SDRplay… get the spectrum, band scan and RF controls instead of only decoding through SDR++. A big change to the input code, better proposed upstream.
- [ ] **Test harness in the repo.** The stand-in librtlsdr that synthesizes signals (for testing without a dongle) and the activity-module unit tests only exist in scratch directories. Commit them, e.g. under tools/, after replacing real frequencies and IDs with made-up ones.
- [ ] **AM for analog voice.** An "Analog AM" decoder next to "Analog FM (no digital)", for airband (118–137 MHz) and other AM voice.
  - The RTL demod comes from rtl_fm, whose `am_demod` (the envelope, √(I² + Q²)) was left out. Add it back in rtl_sdr_fm.cpp with a switch the web flips while running (FM de-emphasis off meanwhile), next to the other `rtl_dev_*` additions. Choosing any other decoder switches back to FM.
  - The rest exists: the DC blocker removes the carrier, and the analog path has the squelch (Auto floor works as is, it measures RF), audio AGC, filters and browser audio. Bookmarks can store the mode.
  - RTL input only (with SDR++, pick AM there); no digital decoding while it's on. About 50 lines, plus an AM station type in the stand-in librtlsdr to test it.
- [ ] **Sweep the spectrum without retuning.** Step through the carriers inside the current span by moving a software VFO instead of the dongle: a frequency shift (NCO) on the IQ before the channel filter in rtl_sdr_fm.cpp, so the demod listens at center + offset while the capture stays where it is. No PLL settling or samples from the old frequency between steps, and the spectrum doesn't jump. The band scan's peak finder (`bs_find_peaks`) can supply the carriers; the page needs a VFO mark on the spectrum. Only the clean part of the capture is usable (see the spectrum edge alias item).
  - A toggle picks how frequencies change. On, they stay fixed jumps: the dongle retunes to each one, as today, and the spectrum recenters. Off, they sweep: the VFO moves inside the span, and the dongle retunes only for a frequency outside its clean part. The band scan, Auto-tune and the planned bookmark scan must each work in both modes; sweeping, the bookmark scan can visit all the bookmarks one span holds with a single retune.
  - Probably simple: every retune in the web layer goes through `do_tune` (src/dsd_web.c), so the choice can go there. Besides that, the band scan's window steps (`bs_tune_window`) place the dongle itself between channels and read the noise reference there, so they retune, with the VFO at zero offset, in both modes. Auto-tune's peak search (`run_auto_tune`) and the band scan's check that the probed carrier is still on air (`bs_center_snr`) read the bins in the middle of the spectrum; sweeping, they need the bins around the VFO.
  - Upstream's own retunes (trunking, the conventional scanner, the ncurses UI) call `rtl_dev_tune` directly and stay fixed jumps, so `rtl_dev_tune` has to clear the VFO offset.
- [ ] **Scan bookmarks.** Scan the bookmarks themselves: the ones ticked in the list, or all of a group or tag (bookmarks have a group but no tags yet), each with its own decoder. Today "From bookmarks" only copies the first 26 filtered frequencies into the conventional scan list, which holds 26 and runs one decoder for all of them. Needs a way to pick bookmarks, a dwell and hang time, and skip and hold keys like the Trunking card's. Tune through `do_tune`, as the band scan does, so it works with both modes of the sweep item's toggle.
- [ ] **Survey every carrier of a band-scan window at once.** The band scan still visits the carriers of a window one after another, about 3 s each when nothing is heard. Cut each one out of the spectrum's IQ instead: an overlap-save filter bank over the IQ ring in src/dsd_spectrum.c (its FFT can be shared), an FM discriminator per carrier, and one sync detector (src/dsd_web_detect.c) and one set of CTCSS/DCS detectors (src/dsd_web_analog.c, made per channel) on each. A window would then take a few seconds whatever it holds, and the decoder would only visit the finds to confirm and name them. RTL and rtl_tcp only, since the other inputs bring no IQ.

## Upstream bugs seen (report to lwvmobile/dsd-fme)

- `getFrameSync` (dsd_frame_sync.c) copies the 24 symbols before `synctest_p` (48 for EDACS) without checking that many have been read, so it reads before `synctest_buf` right after entry for the short frame types (M17, NXDN, dPMR) and after the buffer wraps. AddressSanitizer flags it without `--web` too.
- `-b` clamps the key number to 256, but `BPK` (include/bp.h) has entries 0–255, so `-b 256` reads past the end of the table.
- A UTF-16 talker alias switches the whole process to the environment's locale: `dmr_talker_alias_lc_decode`'s 16-bit branch (dsd_alias.c) and three places in nxdn_element.c call `setlocale (LC_ALL, "")` for `%lc`, and ncurses (`-N`) does the same at start. From then on numbers print with the user's decimal separator, e.g. `NMEA / LOCN; ... (-12,34567°, -45,67890°)` under es_AR, where the comma also separates latitude from longitude, and so do LRRP lines and files. `setlocale (LC_CTYPE, "")` is all `%lc` needs. The web layer keeps C numbers on the decoder thread since 2026-11-07 (`web_c_numbers`, src/dsd_web.c): before that the page's status and activity stopped updating at the first such alias.
- `rtl_return_rms` (rtl_sdr_fm.cpp) smooths with `(prev_rms * 3 + sr) / 4` in integers, which truncates: any value up to 3 under the input is a resting point, so the RMS reads 2–3 counts low (about 10 % on a quiet channel at low gain). Minor; the web's Auto floor squelch just sits that much further over it.
- P25 response packets that carry a block (SACK) go through `p25_decode_pdu_data`, which reads their status byte as a SAP, so the console reports them as encrypted or unknown IP data. The web log decodes them correctly.
- `playSynthesizedVoiceMS` (src/dsd_audio2.c) declares `short mono_samp[len]` with `len = state->audio_out_idx`, which stays 0 for the single-channel decoders with `-o null` (see the browser voice item above): a zero-length variable length array, which UBSan reports while NXDN48 voice decodes. Harmless as compiled.
- AddressSanitizer on 2026-10-21 also reported a stack overflow in `ysf_soft_decision_viterbi` (AUTO mode on noise), a memcpy over-read in dmr_dburst.c and undefined shifts in dmr_block.c and `dmr_locn`. Re-check on current upstream before reporting.
- Two out-of-bounds reads that GCC flags at `-O2` (`-Waggressive-loop-optimizations`); GCC still compiles both loops as written, so the optimized build runs them as the `-O0` one does:
  - `vertex_40_keystream_creation` (crypt-rc4.c) prints 8 bytes of the 4-byte `rc4_bytes`, so the console shows 4 bytes of whatever follows it on the stack.
  - `processYSF` (ysf.c) loads the IMBE vector c7 from bit 7 down, though c7 holds 7 bits (P25 fills 6 to 0), so it reads `imbe_vch[144]`, one past the end, and every c7 bit lands one place off.
